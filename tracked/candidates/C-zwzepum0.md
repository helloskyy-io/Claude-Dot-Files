**DISTINCT FROM C-523klr8n AND THE SPLIT IS THE USEFUL PART. C-523klr8n is about a figure RESTATED in two places; this is about a claim ASSERTED once and false.** Measured on one PR: four wrong load-bearing prose claims, and they split cleanly into the two classes. C-523klr8n's class — the phase doc's `is_error` and `parse_verdict` citations, dead line numbers and counts moved by the PR's own diff; and `review_pr_workflow`'s docstring naming FIVE deferred pure functions with nothing enforcing the set. **The other class is what this row is for, and neither a restatement gate nor a resolve-check can see it:** (1) `review_pr_helper.completion_ref_mismatch_note` told an operator, at the moment of the failure, that the field's number *"flows into `gh pr view`, `gh pr comment` and `--pr`"* — nothing in the tree reads `completion_ref` for anything but that comparison, so a reader would have believed a cross-PR WRITE was averted and stopped looking, while the derivation that does reach `gh` was unguarded; (2) `disposition.md` told the child that a quoted prior block *"is now correctly ignored either way"* — `thread_snapshot` keeps only the LAST block per comment, so a quoted block placed below the child's own displaces it entirely and no nonce rescues it. **Both were syntactically fine, both cited real files, and both were false about what those files do.** **Consequence, and it is why the class is worse than the restatement class: a false statement in a file readers are trained to trust actively STOPS the next person checking** — a docstring is read instead of the code it describes, and a prompt sentence is followed instead of the parser it describes. **PROPOSAL, not a defect.** Both instances are fixed in the PR that found them; what does not exist is any rule or check covering the class. **Done-state, and it is deliberately the small half: a stated convention in the documentation standard** — *a comment asserting the behaviour of code in another file names the test that holds the claim, or states the claim as of a date, or is not made* — plus the observation that the repo ALREADY applies this well where it applies it at all (`SINGLE_CONSUMER_PARENT_MODULES`, the AST gates, the negative controls) and has simply never decided the boundary between prose-that-is-a-control and prose-that-records-a-measurement. **NOT proposed as a regex gate, and that is a finding rather than a gap:** C-8rhxo6st's row records that a prototype for the adjacent status class returned 9 hits of which 2 were real, and a cross-file behavioural claim has strictly less syntactic signature than a status. Proposing a gate here would be proposing a thing nobody knows how to build. **Not an expansion of C-523klr8n:** C-523klr8n's remedy is *derive rather than restate*, which is unavailable here — there is no second copy to derive from, only a claim about another file. Applying C-523klr8n's remedy to this class would produce nothing.  **AMENDED FROM PR #83 (research_minor, refine pass) — three more instances, and they identify a SUB-CLASS with a cheaper remedy than the general rule.** All three are **stale CROSS-REFERENCES**: a sentence naming a location in another document that was correct when written and was falsified by a later edit somewhere else. (1) `research_activities.upstream_block()` ended with *"Your sizing in Stage 2 must state which topics upstream already covers"* — true while `research_write` was its only consumer, false the moment `research_write_minor` injected the same block into a prompt with no sizing stage, which then ordered an assessment that prompt separately forbids. (2) `research_verify/prompts/verify.md` opened Stage 1 with *"For each paper written or updated in Stage 3"* — a reference to a DIFFERENT workflow's stage numbering, which the minor cycle does not share. (3) Two new workflow docstrings cited *"Research Standard §3"* for the sizing rubric, which lives in **§2** — and the same PR's own C-xhb460zu row cited §2 correctly, so one artifact disagreed with itself. **Why this sharpens rather than merely corroborates C-zwzepum0:** the general class ("a claim about how another file behaves") was judged un-gateable — the row itself records that a prototype for the adjacent status class returned 9 hits of which 2 were real. **This sub-class is different, because both halves are syntactically distinctive and mechanically checkable:** a `§N` citation resolves against the target document's own headings, and a `Stage N` reference resolves against the cited prompt's `## Stage N:` headings. Neither needs to understand behaviour — both are name-resolution, the same shape as the link-checking this repo already does. **That makes a gate proposable here where it was not proposable for the parent class**, and it is offered as a narrowing of C-zwzepum0's done-state rather than as a separate row. All three instances were fixed in PR #83. **AMENDED FROM PR #132 (`plan-verify` preflight, correction passes 3-7, 2026-08-20) — a SUB-CLASS that turns the parent class INWARD, and it is gateable where the parent was not.** The parent class is a claim about how ANOTHER file behaves. This sub-class is **a claim about what a GATE IN THE SAME FILE holds** — a test docstring, or a Decision Log sentence, asserting coverage the assertion underneath it does not have. **Why it is gateable where the parent class was judged un-gateable:** C-zwzepum0's own Note records that a prototype for the adjacent status class returned 9 hits of which 2 were real, because a cross-file behavioural claim has almost no syntactic signature. An unbounded universal quantifier inside a test docstring does — *however it is phrased*, *any future rewording*, *this keys on the CLASS* — and the repo already ships two members of exactly this family (`scripts/workflows/temporal/tests/unit/test_promotion_guard_prose_figures_are_DERIVED.py` and `.../test_a_prose_COUNT_of_a_collection_is_DERIVED.py`), so the shape is known buildable rather than hypothetical. **THE MEASURED INSTANCE, with evidence rather than narration.** The docstring shipped at `142421a` claimed *“any future rewording that re-sweeps the phase-doc count into a blanket zero claim fails here however it is phrased”*, and that run's Decision Log repeated it as *“this keys on the CLASS”*. Review pass 5 restored the over-claim **by rewording alone** and the module ran **71 passed, 0 red** — the gate written to stop an over-claim was itself the third over-claim, and no code mutation could have reached it. **Three altitudes, one class, one PR, each found only after the previous was fixed:** the dry-run caveat over-claimed which counts go to zero; the refusal's remedy over-claimed what the operator should do; the test written to stop the caveat over-claiming over-claimed what it caught. **PROPOSAL, not a defect.** All three instances are fixed in PR #132 — the shipped docstring now carries a *WHAT IT DOES NOT HOLD* paragraph bounding its claim to a necessary condition, and the gate was verified discriminating by mutation (the over-claim restored → 1 red, in the intended test and only it). What does not exist is any check covering the class. **Done-state today, stated plainly because the placement rule turns on it:** a gate over test docstrings that flags an unbounded universal quantifier about what the test catches unless the same docstring states its limits — the `WHAT IT DOES NOT HOLD` shape this PR ended up writing by hand. That is a closable unit of work with a done-state today, not a trigger-gated one. **Distinctness, in this file's convention.** NOT issue #103 (twelve *structural tree-walking* guards with no positive control, an enumerated list with a shrink-only exemption — `test_plan_verify.py` walks no tree and is on none of those lists). NOT C-523klr8n, whose remedy is *derive rather than restate* and needs a second copy to derive from; here there is one claim and nothing to derive it from, only a bound to state. NOT C-f0lfdhmm, which asks what a MUTATION should probe — a technique for the reader, not a check on the prose. It **narrows C-zwzepum0's done-state** rather than opening a row, on the PR #83 precedent recorded immediately above.
