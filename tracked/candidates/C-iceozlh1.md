**`verify.md` already NAMES this defect and deliberately does not fix it** — *"The real defect is that a correction round re-verifies everything rather than what changed — `author != judge` needs a fresh JUDGMENT, not a fresh DOWNLOAD, and this stage conflates them. Until that is rebuilt, 3 bounds the damage."* The 3-round ceiling is therefore a **damage bound standing in for a capability**, and the capability is what this row proposes. **The cost the bound was set against, from `verify.md`'s own measurement of PR #84:** five critic passes over 28 sources re-fetched from scratch every round, **$58.62 and 135 minutes in this stage alone — six times the $9.14 the paper cost to write** — at 441 Bash calls against 1 WebFetch. **Measured on THIS PR, which is the new half:** round 1 ran the full pass (18 external sources, every git-hosted span by shallow-clone + `grep -F`); **rounds 2 and 3 were scoped to the repaired spans only, re-cloning nothing**, on the basis Research Standard §3 already states — *"A repaired span is a new claim"*, carrying an original's full sourcing burden. **Scoping did not cost detection: round 2 found a blocking defect round 1 had missed** (four internal cross-references reading `§4.3.3` where the content is `§4.3.4`), and round 3 closed at PASS with zero blocking. One paper, closed inside the ceiling — one data point toward `verify.md`'s own stated 90%-inside-3-rounds target. **Why this is a finding and not a note: the scoping existed only in the orchestrator's hand-written dispatches.** Nothing in `verify.md` asks for it, so the next run either reinvents it or re-downloads the corpus, and the ceiling keeps bounding a cost that no longer has to be paid. **Done-state today: yes, and small** — a clause in Stage 1 stating that round 1 is the full pass and rounds 2+ verify the repaired spans and their dependents, plus the guard this run had to write by hand: the analyst's span list is **a claim to check against the diff, never a map to trust** (round 3's critic found one genuine edit the analyst's own inventory omitted, and mis-attributed its round because no intermediate commit existed to separate them). **NOT a defect:** nothing behaves wrongly — the stage is correct and expensive, and `verify.md` chose the bound knowingly. **Not an expansion of C-4pr7kq11:** that proposes a normalisation convention in Research Standard §3, a vendored document, so a verifier stops re-deriving what counts as verbatim; this proposes a scope rule in this repo's own `verify.md` so a verifier stops re-fetching what it already checked. Different document, different owner, disjoint remedy. **Not filed as an issue** — capability that would be ADDED, which per [`finding-routing.md` § 4](../../finding-routing.md) makes it a candidate whatever its done-state looks like. *(Id assigned as the next free one on this branch; if a PR merges first and takes C-iceozlh1, this row renumbers on the file's existing rule that ids are never reused.)*
