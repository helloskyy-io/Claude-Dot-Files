**Measured on this file, not estimated.** It records **9 renumbering events across 7 rows** — `C-45bhs5cm`→`C-abieu0fg`, `C-73bf2gvm`→`C-ijmjaqrs`, `C-xhb460zu`→`C-d5m6c9pu`, `C-skkjo6jn`→`C-d5m6c9pu`, `C-abieu0fg`→`C-ifs47g3r`, `C-r2tb9xfi`→`C-ifs47g3r`, `C-hurryucg`→`C-9vb7pluf`, `C-emxcrzti`→`C-ni21k1bd`, and this PR's `C-8z8v04wk`→`C-npx1uwgj` — plus two ids (`C-h2gjrqrb` withdrawn, `C-r2tb9xfi` vacated) that no row ever took. Every one is recorded honestly on the row, and every one breaches the invariant [`candidates.md`](../../tracked/candidates/) states about itself. **THE MECHANISM: each branch allocates "the next free id" from its own snapshot, and the collision is invisible until the merge** — git sees two rows added at different positions and auto-resolves with no conflict, so nothing red says the same id was taken twice. `test_candidate_ids_are_unique.py` catches a duplicate only AFTER the merge lands, when the remedy has already become a renumber. **Ids are cited from outside this file** — issue #98 (closed) cites `C-8z8v04wk`, which is precisely why this branch's own C-8z8v04wk had to yield rather than `main`'s — so id instability degrades citations that cannot be updated from here. **This is a PROPOSAL, not a defect: no id is wrong today.** What does not exist is an allocation mechanism, which is what keeps this out of the issue queue per [`finding-routing.md` § 8](../../docs/standards/finding-routing.md). **Done-state today: yes** — a rule plus a check, one section. The design choice is real and is triage's to rule, not this row's: allocate at merge rather than at write, use non-sequential ids, or add a freshness gate that fails when the id was free in the branch's base and is taken on `origin/main`. Adjacent to C-9vb7pluf/C-ni21k1bd/C-npx1uwgj's shape — a declaration nobody derives — but distinct: those are read-back gaps, this is an allocation gap, and the thing being allocated is the address every other row is cited by. **Lens verdicts (gate 5), recorded by PR #96's `build-refine` correction pass because the filing passes omitted them:** `/decide` — **not dissolved.** The upstream question is whether a sequential id should be the address at all; that is exactly what the row hands triage, and it is an open design choice rather than a mis-framing. `/best-practices` — **SURVIVES.** Collision-free identifier allocation under concurrent writers is a solved class with several standard answers, and the row names three of them. **SHIPPED 2026-08-22 at `2af48df`.** `candidate_ceiling` no longer computes `max + 1`; it mints `C-` plus eight random base36 characters and hands the run three. All 119 existing ids were migrated on the operator's ruling that no legacy shape is carried. The two checks that only meant something under a sequence — the declared id RANGE and the numbering SKIPS — were deleted rather than ported. **`decision` stays blank deliberately**: this shipped before triage ever reached it, which the file already has precedent for, and only `triage-candidates` writes that column.
