**The composition is live on this branch, not hypothetical.** `assistant_activities._GH_RETRY_BACKOFF_SECONDS` `(2.0, 6.0)` was added by PR #101 so a `gh` read survives a transient 5xx; `review_pr_workflow._THREAD_READ_BACKOFF_SECONDS` `(2.0, 8.0)` already retried `RuntimeError` on the thread read so a flaky read could not discard a completed review. The second calls the first, so the attempts **multiply rather than add**: 3 × 3 = **9 attempts, ~34s**, measured and pinned as a literal in `test_the_retry_under_the_review_threads_retry_stays_bounded`. Neither constant's own comment could have told you that, because each is correct about itself. **The consequence is that the bound is only ever knowable by reading both files at once** — an operator asking "why did this take half a minute" has no single number to look up, and whoever edits either tuple next moves the product without touching anything that says so. **Why this is a PROPOSAL and not a defect:** nothing behaves wrongly today; the composed bound is deliberate and asserted. What does not exist is the STANDARD — `docs/standards/workflow-scripts.md` says nothing about retrying an external CLI call. `grep -in retry` over it returns **exactly one** hit, line 429, and it is a different subject: *"every child boundary is a **retry/resume point**"*, about composing workflows for recoverability under durable execution. Checked rather than assumed, because "the standard is silent" is the kind of claim that is one grep from being wrong. So the three decisions PR #101 had to make were each made from first principles: retry only idempotent reads (a 5xx on a mutation may mean it landed and the reply was lost — issue #41 records duplicate comments as a real harm here), classify on the HTTP status rather than server-supplied prose, and state the composed bound wherever policies nest. **Done-state today: yes** — one section in an existing standard, with the two live policies as its worked example. **Surfaced rather than written because `docs/standards/` is human-in-the-loop**; this row is the placement, per `finding-routing.md` § 4, and the standards file itself is untouched by that run. **Adjacent to, and distinct from, the CPI rows about undeclared counts (C-9vb7pluf/C-ni21k1bd/C-npx1uwgj):** those are declarations nobody derives, this is a decision nobody wrote down, and the artifact is a standard rather than a gate. **And distinct from C-c5y9uqhk, the one row sharing its exact keyword — checked by mechanism rather than by phrase, per [`finding-routing.md` § 5](../../finding-routing.md) gate 2.** C-c5y9uqhk is a *Temporal SDK* activity-level `RetryPolicy` on a future worker runtime, whose failure mode is Temporal's unlimited-attempts default re-charging a paid API; this is a hand-rolled `subprocess` backoff around the `gh` CLI in the pre-Temporal fleet, whose failure mode is a composed bound nobody has written down. They do not overlap today and they will not merge later: when workers land, C-c5y9uqhk governs the activity wrapper and this still governs what the wrapper calls. Recorded because the two read as duplicates from their titles alone, and the next reader should not have to re-derive that they are not. **Lens verdicts (gate 5), added by this PR's fourth correction pass after `standards-auditor` found them missing — the same omission a `build-refine` pass on PR #96 was already spent correcting on C-yi65bngf, which is why it is recorded rather than quietly filled in.** `/decide` — **not dissolved.** The upstream question is *whether a retry policy belongs in a standard at all, or is a per-caller judgement*, and the composition answers it: two policies written independently, each correct about itself, multiply on one path to a bound neither states. That is precisely the class a standard exists for — a decision no single author is positioned to make. `/best-practices` — **SURVIVES.** Bounded retry with jittered backoff, an idempotency gate on which operations may repeat, and a STATED ceiling are settled industry practice (AWS Architecture Blog on exponential backoff and jitter; Google SRE Ch. 22 on cascading failure, whose whole subject is retries composing); what is not settled and is this candidate's actual content is *which bound a policy must state* — attempts, added latency, or wall clock. This PR's own comment stated added latency and was read as stating wall clock, which is the worked example. **Neither lens narrows the scope, and neither resolves it into a known fix** — the mechanism (a section in `workflow-scripts.md`) is obvious; what a human must rule on is whether a standard should mandate stating the composed product, which is a cost on every future retry author.
