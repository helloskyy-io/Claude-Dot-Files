**`plan-candidates` decides *extends an existing component* versus *is a new one* by EXACT SLUG EQUALITY** — `docs/development/<slug>/` either exists or it does not. A filer writing `memory-management` against the tree's `memory-management-framework/`, or `temporal` against `temporal-integration/`, therefore gets a SECOND directory beside the real one, plus a `research-write` and a `research-verify` dispatch into it. **That is two homes for one item, which this file's own § Why it exists names as the failure it was built to end.** **The filer cannot check, and that is the substantive half.** The filing instruction lives in `prompts/decision_log_and_reflection.md`, which is injected into every producing workflow, and it says *"an existing `docs/development/<name>/` if it extends one"* — to a run that is handed no enumeration of those names. `act.existing_work` already renders exactly that list, but only into `triage-candidates`, `plan-sprint` and `plan-revision`, none of which is where most rows are filed. So the instruction asks for a comparison against a set the reader cannot see. **The remedy is prompt-side, not code-side, and the distinction is the whole reason this is a candidate rather than a fix.** Rendering the component list into the shared filing fragment changes how a prompt shared by twelve workflows is composed — genuinely outside a `plan-candidates` PR. **A fuzzy-match guard in the activity was considered and REJECTED**: `difflib.get_close_matches` would make the scaffolder decline a legitimately new component whose name resembles an existing one, and the operator's stated basis for building this as code at all is that *"it needs no judgement, which is why it is code"*. Adding a similarity threshold gives it judgement, and a wrong skip is as expensive as a wrong fork. **Done-state today: yes, and small** — one `${EXISTING_COMPONENTS}` substitution in the shared fragment, populated from a directory listing. **NOT a defect:** every documented condition behaves as specified and every test passes; nothing has forked yet, because on the tree as of 2026-08-13 exactly one row names a component at all. This proposes closing a gap the design leaves open. **Not an expansion of C-6umbp67a:** that carries the Note's EVIDENCE into the seeded synthesis — what the seed says once the component is chosen. This is about choosing the component in the first place. Disjoint remedies, different files, neither subsumes the other. **Not filed as an issue** — capability that would be ADDED, which per [`finding-routing.md` § 4](../../docs/standards/finding-routing.md) makes it a candidate whatever its done-state looks like. *(Id taken by re-reading this file at HEAD and comparing against `origin/main` immediately before writing: `origin/main` ran to C-l2doi8ox, this branch to C-6umbp67a.)*
