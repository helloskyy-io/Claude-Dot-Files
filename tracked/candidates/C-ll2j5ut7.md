**Two independent reviewers converged on the same seam, in the same pass, without conferring.** `refactoring-evaluator` (High) and `quality-control` both scoped the split OUT of PR #101 and both named `modules/assistant/github.py` — the `gh` layer, one concern, a clean surface. Recorded here so the seam is not re-derived by whoever reads this file next. **Measured in this branch, not remembered:** `wc -l` → **1307** lines; an `ast` walk of the module's top level → **27** functions, **1** class, **11** module-level constants; **6** of those functions are the `gh` layer (`_gh_transient_reason`, `_gh_is_read_only`, `_gh_timed_out_line`, `gh_attempt`, `gh`, `gh_json`) together with **3** of the constants (`_READ_ONLY_GH_VERBS`, `_GH_RETRY_BACKOFF_SECONDS`, `GH_JSON_SHAPES`). `git diff --numstat origin/main...HEAD` → **+551/-20** on this file in PR #101 alone, so the growth is recent and attributable rather than ambient. **Why this is a PROPOSAL and not a defect:** nothing behaves wrongly. The module is correct, tested, and its `gh` layer is the most heavily guarded code in the tree. What does not exist is the extraction, and the reason it does not is a genuine gap rather than an oversight — **[Temporal Standard](../../temporal/) §10.1 rule 3 promotes a shared module to the PARENT MODULE LEVEL, and all three importers of `shared.run_bounded` (`assistant_activities`, `build/build_activities`, `plan/plan_activities`) are already under `modules/assistant/`, so the rule is satisfied where it stands and is SILENT on whether a 1307-line module should be split for size alone.** PR #101's producing run rejected the extraction on exactly that reasoning and the `review-pr` pass verified the reasoning as sound; the silence is what makes it a human question rather than a conformance failure. **Done-state today: yes** — one extraction, one new module, no behaviour change, with the six functions and three constants above as the worked boundary. **The trigger that would force it anyway** is a third non-assistant consumer of the `gh` layer, which is already recorded in PR #101 as the revisit condition for the sibling question about `run_bounded`'s home. **Distinct from C-lg7lpge9, the only adjacent row — checked by mechanism, per [`finding-routing.md` § 5](../../finding-routing.md) gate 2.** C-lg7lpge9 asks what a *standard* must say about retry policy for external CLI calls; this asks where the *code* implementing one should live. C-lg7lpge9's artifact is `docs/standards/workflow-scripts.md`, this one's is a Python module. Neither blocks the other and delivering either leaves the other untouched. **Placed rather than surfaced because the PR body is not a home.** PR #101's fourth pass recorded this under "Surfaced — no verified home", and `review-pr` pass 3 held the PR on it: a proposal left in a PR body dies at merge, and `candidates.md` is the home the same run had already used for C-lg7lpge9. **Why [`finding-routing.md`](../../finding-routing.md) § 5 gate 0 does not reach this, stated because the row is a precedent the next run will read.** Gate 0's closed list — `fixed`/`rejected`/`hold`, with `candidate` explicitly unreachable — governs a finding ABOUT THE WORK IN HAND, and PR #101 does touch this file. It does not apply because § 2's Question 0 comes first and answers PROPOSAL: `assistant_activities.py` is a pre-existing module that behaves correctly, the split is capability that does not exist, and § 3's selection rule and gate 0's list are both written for a DEFECT. § 4 then grants a producing run the right to place its own proposal in its own PR. The distinction that makes this checkable rather than arguable: a gate-0 finding names something WRONG in the diff; this names something ABSENT from the tree. **A run reaching for this precedent should test its own item against that sentence, not against this one.** **Lens verdicts (gate 5).** `/decide` — **not dissolved.** The five-whys bottoms out at *why is there no rule for when a module is too large*, and the answer is that [Temporal Standard](../../temporal/) §10.1 rule 3 answers a different question (which LEVEL a shared module is promoted to) and is satisfied here, so nothing in the corpus is positioned to say whether 1307 lines across seven concerns is a defect or a preference. That is an unresolved upstream question, not a dissolved one. `/best-practices` — **RESOLVES INTO A KNOWN FIX, and that is the finding.** Extract-module against a single-concern seam is settled practice with a named mechanism, an agreed safety property (no behaviour change) and an obvious verification (the suite). What is NOT settled by any external source is whether to spend it here and now, because the cost is a 1307-line file's import surface moving under four other modules mid-PR. **So the two lenses disagree in a way that is itself the argument for filing rather than doing:** the mechanism is known and the timing is a judgement, which is exactly the shape `triage-candidates` exists to rule on and the shape a correction pass must not rule on alone.
