**PROPOSAL against a VENDORED (MIRROR) standard — placed here rather than made, because `docs/standards/testing/` must not be edited in this repo and an amendment goes upstream to MDC-Master-Planning then re-vendors. Same mechanism as C-d5m6c9pu and C-4pr7kq11.** **The consequence, and it is why this is a finding rather than a note: the standard's silence prices COPYING at zero and the correct answer at a design decision.** A test module needing a helper that a sibling already has faces three options with no rule between them — copy it (two definitions that drift), import the sibling test module (a module pytest COLLECTS rather than imports, which is the coupling `review_run_fakes.py`'s own `file_structure.txt` annotation records as having broken at collection, issue #72), or invent a non-`test_`-prefixed module in `tests/unit/` and hope that is sanctioned. **The drift arm is not hypothetical and this repo has paid for it twice**: `plan_activities.normalise_cell` exists because two hand-written normalisations of one cell diverged and a row read RULED to one reader and BLANK to the other, and this PR removed a second instance in the making. **Two independent instances now exist and neither was guided by a rule** — `review_run_fakes.py` (the review_pr fakes) and `observer_registry.py` (the shared registry-entry resolver) — each arriving at the same shape by reasoning it out from scratch. A standards audit of this PR classified the placement as *tolerated by precedent rather than codified*, which is exactly the state in which the third instance goes the other way. **Done-state today: yes, and it is one sentence** — a clause in the Testing Standard's tier section stating that a helper shared by two or more test modules in a `tests/` directory lives in a sibling module without the `test_` prefix, named for its purpose, and is entered in the repo map like any other file. **NOT a defect:** nothing behaves wrongly, both existing helpers are placed correctly, and every test passes. The standard is silent, not incorrect. **Not an expansion of C-45bhs5cm, C-73bf2gvm or C-xhb460zu:** those concern the mutation probe's exit semantics and telemetry retention — different document, disjoint remedy. **Not an expansion of C-ifs47g3r:** that is about four DRIFTED prompt copies under a rule that already binds and was already crossed; here no rule exists to cross. **Not filed as an issue** — capability that would be ADDED to a document, which per [`finding-routing.md` § 4](../../docs/standards/finding-routing.md) makes it a candidate whatever its done-state looks like, and the default is against filing. *(Allocated C-iceozlh1, not C-4pr7kq11: PR #84 landed C-4pr7kq11 and C-xh8nvwqn on `main` while this branch was open — checked with `git show origin/main:…/candidates.md` immediately before writing this row, per this file's rule that an id is never reused.)*
