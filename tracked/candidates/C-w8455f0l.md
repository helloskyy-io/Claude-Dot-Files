**The consequence, measured on this PR rather than predicted: four defects shipped past a registry that reported full coverage, and three of them were mechanisms that did not cover what their own row claimed.** `test_authorization_is_observed` proves a row names a symbol that RESOLVES; `test_disappearance_is_observed` proves a snapshot is CLAIMED. Neither invokes a mechanism against the row's own scenario, and the gap between *a mechanism exists* and *it fires on the case it names* is where all four sat. **What was actually found here:** `malformed_phase_docs` was sourced from a `^phase` sweep, so `the_run_bag.md` — the standard's first-named failure mode and the likeliest one — was invisible while the row said that function observed it; the hour and checkbox guards were scoped narrower than the write grant, leaving a permitted file nothing read; and the phase-identity message was unreachable because a broader guard raised first. **Done-state today: yes, and the shape already exists** — `observer_registry` discovers rows and mechanisms by AST, so the addition is a third assertion requiring each mechanism symbol to appear in a behavioural test module, the same way `test_the_two_candidate_READERS_ALWAYS_KEY_THE_SAME_ROWS` holds a coupling a registry entry merely asserts. **Not an expansion of C-gbclnzsq:** that gates QUOTATIONS in prose against the file they name. This gates a REGISTRY ENTRY against the behaviour it claims. Disjoint mechanisms, disjoint failure classes. **Not a defect in what this PR built** — every defect it names is FIXED in this PR; what does not exist is the gate that would have caught them, and would catch the next one on `plan-sprint` or `triage-candidates`, whose registries have the same property. **Not filed as an issue** — capability that would be ADDED, per [`finding-routing.md` § 4](../../docs/standards/finding-routing.md).
