**Measured on this PR, not projected.** `review-pr` checked four anchors and found **two already dead**. Repointing the six papers measured the rest: of the **ten** `§`/milestone anchors those six carry, **six were dead and four resolved**. The six: three headings that no longer exist (`Where this repo sits`, `Why coding is the first edge, and not merely the earliest`, `Affordability is not a footnote — it is the enabler`, all reworded or deleted in `problem-statement.md` on 2026-08-20/21), and three milestones of a document that was never written. **And one of the four that RESOLVED is worse than any of the six**: it lands on a live heading (`Where we actually differ`) while quoting a claim wording (`Edges are dedicated and non-fungible`) that has since been rewritten, so the reader arrives and reads a different claim without being told anything moved. **THE FILE CHECK WAS GREEN ON ALL OF THEM.** **Two more dead targets are invisible for a different reason:** `_FEEDS` matches one line, so a target on a WRAPPED continuation line is never read — `backbone_edge_generality.md` names a `system-overview.md` that has never existed anywhere in this tree, and `dedicated_edge_routing.md` names a bare `roadmap.md` that resolves from neither the repo root nor the paper's own directory — the same dissolved-destination class the eight `docs/development/roadmap.md` papers are baselined for. Both are outside the baseline because the guard cannot see them, so they are not even counted as rot. **`candidates.md` Notes are the third surface** — same class of stale pointer, different owner, no watcher at all. **What breaks without it:** a planner follows an anchor, lands on a real file, cannot find the section, and has no way to tell a misfiled paper from a moved heading — which is the exact harm the file-level guard was built to stop, one level down and currently unguarded. **Distinct from `C-9yi1yv2h`, which asks what STATE a paper is in when its destination legitimately dissolved** — a Research Standard clause, not a check. This is the check, and it assumes the destination still exists. **Not a defect:** nothing behaves wrongly, the guard's scope is stated honestly in its docstring; this is capability that would be ADDED. **Done-state today: yes** — an anchor resolves or it does not, and all three surfaces are readable from the tree with no trigger to wait on. **Deliberately NOT built on this PR:** its scope is five named findings, and a sibling PR that generalised a one-line fix into a 604-line guard spent four passes repairing the guard.
