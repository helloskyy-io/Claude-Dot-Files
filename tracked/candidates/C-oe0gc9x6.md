**Both gates were built on `candidates.md` and are scoped to it; the class is not.** Measured on this PR: a 1,981-character line sat inside the candidate table and rendered through GitHub's `POST /markdown` as a DETACHED row — its whole text in the ID column, six empty cells beside it — while C-523klr8n's Note was cut from 8,633 characters to 6,677, losing exactly the evidence a triage pass is meant to weigh. Nothing was red: the stray carried no `C-NNN`, so no derived count counted it and none missed it. **Then the same two predicates were run over all 228 tracked `.md` files: zero further stray lines, and TWO live cell-count mismatches that nothing gates** — `phase4_fleet_migration.md:69` (7 fields against a 5-field header) and `memory-management-framework/roadmap.md:269` (5 against 4). Both truncate a planning table's right-hand cell today. **UPDATE — PR #96's fifth correction pass (2026-08-17) fixed both instances AND shipped the gate, so the sentence that stood here saying they were "deliberately NOT fixed" is no longer true and has been struck rather than left to mislead a triage pass.** `testing/scripts/tests/unit/test_markdown_tables_render_whole.py` now checks every row of every table block in all **228** tracked `.md` files against its OWN header, importing `_table_blocks` and `_cells` from the sibling rather than copying them, because two definitions of *inside a table* is the drift this row is about. Both questions this row called open were answered by **measurement rather than ruling**: the population is every tracked `.md` **including** the vendored mirrors — 11 files, 10 carrying tables, all clean — whose remedy when red is upstream-then-re-vendor and is stated in the gate's own limits list; and fenced code blocks are excluded because `POST /markdown` returns **zero** `<table>` elements inside a fence, which makes any finding there a false positive by construction (two such tables exist today and both are internally consistent, so the exclusion is not what makes the gate green — proven by mutation: gutting it left the tree-wide check passing). **What remains for triage is narrower than this row was filed for:** whether the HTML-block residual should carry CommonMark's fixed tag list. Measured — `<div>` ends a table for GitHub and `<span>` does not, and **zero** tracked files have a `<`-opening line inside a table block today, so the residual is real and unexercised, and it is held red-able rather than left as prose. `decision` and `status` are deliberately untouched by that pass: reporting what shipped is not ruling on the candidate. **Lens verdicts (gate 5):** `/decide` — **not dissolved.** The upstream question is *whether a markdown table's RENDERING is a property worth gating anywhere but here*, and it is: two live truncations sit in files this repo treats as authoritative today, found by the same instrument and cited above. `/best-practices` — **SURVIVES.** Verifying a source artifact in the representation its consumer reads is ordinary practice (link checkers, schema validators, snapshot rendering), and the mechanism already exists — this is a population change, not a new instrument. **Not resolved into a known fix:** which files count as authoritative, and whether the scan must carry CommonMark's fixed HTML-block tag list (measured: `<div>` ends a table, `<span>` does not, so a blanket `<` test would invent failures), are design decisions rather than line changes.
