**RESOLVED 2026-08-14 upstream (`1ffbc27`): §0 is now its own top-level section, with the decision binding everywhere and the artifact shapes staying with the layout section.** This is the THIRD instance of one structural hazard in the same vendored document, and the first two are already recorded in [its own README](../../docs/standards/documentation/README.md).** §0 (`documentation_standard.md:69`, `### 0. Component vs phase — what gets a folder (binding)`) states a rule that depends on nothing about a repo's folder layout — *every planning doc is either a new component with a roadmap, or a phase of an existing one; there is no third category.* It sits inside `## Development Planning Files` (line 65), which `README.md:36` excludes wholesale: *"assumes the master-planning layout."* **So a rule marked `(binding)` does not bind here, by structure rather than by anyone's decision.** **The consequence, measured on this very run:** the dispatch brief asserted *"Documentation Standard §0 is binding"*, which is false as cited, and a run that took it at face value would have propagated a wrong binding-standard citation into a new component's roadmap — **the exact defect class the workflow's own Stage 1 warns about, and which it has already produced once in a phase's sizing.** This run caught it and cited `sprint.md` for authority instead, but the next one starts from the same false premise. **The precedent is exact and it is upstream's own:** `README.md:34` records that `§ Completion checkboxes` was structurally swallowed by the Sprint-Tracking exclusion, a producing run read it that way on 2026-08-09 and *"was not being careless"*, and **upstream promoted it to its own top-level section the same day**, retiring the hazard for every consumer. `README.md:38` records a third case where a carve-out *"swallowed the clauses beside it."* The same remedy applies unchanged. **PROPOSAL against a VENDORED (MIRROR) standard** — `docs/standards/documentation/` must not be edited here; the amendment goes upstream to MDC-Master-Planning and re-vendors, same mechanism as C-d5m6c9pu and C-4pr7kq11. **Done-state today: yes, and small** — move one subsection up one level. **Not an expansion of C-4pr7kq11:** that is the Research Standard's §3 sourcing rules. Different document, different section, disjoint remedy. **Not a defect:** §0 is correct and internally consistent; only its placement is wrong, and this repo has a local authority (`sprint.md`) that covers the same ground, so nothing behaves wrongly today. **Not filed as an issue** — capability added to a document, per [`finding-routing.md` § 4](../../docs/standards/finding-routing.md).
