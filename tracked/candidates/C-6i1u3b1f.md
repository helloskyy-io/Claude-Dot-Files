**The consequence, and it is the component's own thesis coming true about the component.** PMP Phase 3's write-path inventory has two halves. The fleet-code half is wrapped at the call site and held by an enumerating sweep in the shape Phase 1 r11 established. The model-issued half — the child itself running `gh pr comment` — has no call site to wrap, and its stated mechanism is a post-exit harvest with a stated failure mode of its own (a comment posted after the harvest window is not captured). **What guards each half is asymmetric and the docs say so.** Phase 3 § *The write-path inventory* states outright that *"a build that enumerates only the first half populates the table, wires every row, closes requirement 1, and never emits a single PR comment — and nothing goes red"*, and Phase 3 r12's activity boundary *"does not reach model-issued writes at all"*. The only thing standing behind the harvest is one checklist item — demonstrate one `research_minor` cycle whose PR body and comments appear verbatim — which is a one-time demonstration, not a check. **And Phase 4 does not close it either, on Phase 4's own reading.** Its negative test (r3: delete one emit, the test goes red) is scoped to the stores in the test set, which r1 names as `candidates.md` and `direction.md`; § *Which stores are in the test set* says GitHub-hosted surfaces are *"the expected hard case"* and may land in r5's not-covered table instead. If they do, the harvest half has neither a rebuild test nor a standing test, and the guarantee decays silently in exactly the way this component exists to prevent — on the half the operator's design test names, which is the PR body, the decision log and the reflection comment. **Remedy, and the shape already exists in this repo.** A standing check for the harvest half in the family of `test_every_parent_opens_a_run_bag` — either an enumerating sweep asserting that every workflow which posts to a GitHub surface produces a harvested completion in its own bag, or a per-run reconciliation counting store-side comments against harvested completions and failing on a shortfall. **Which of the two is a build decision; that there must be one is the proposal.** **Not a defect: Phase 3 is not started, so nothing built today behaves wrongly.** This is capability that would be ADDED, per [`finding-routing.md` § 4](../../docs/standards/finding-routing.md). **Not an expansion of Phase 4 r3**, which asks that an existing in-test store's emit be removable-and-caught; this asks for coverage of a half that r3's test set may not contain at all. Surfaced by the cold read that sized this component; `decision` is blank because triage has not happened.
