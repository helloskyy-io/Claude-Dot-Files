lllllll# Hierarchical Agent Architectures and Long-Horizon Planning

*Source material for §3.2 (hierarchical composition of reflective loops) and §4 (theoretical analysis) of "Beyond In-Memory Reflection: Durable Execution as the Substrate for Long-Horizon Self-Improving Agent Systems in Software Engineering."*

## 1. Why Hierarchy: The Failure Modes of Flat Agents at Long Horizons

Empirical evidence from the 2025-2026 long-horizon agent literature converges on a single quantitative observation: monolithic ReAct-style agents degrade sharply once trajectory length exceeds a threshold on the order of thirty tool calls, or roughly thirty-five minutes of wall-clock reasoning. Zylos (2026a) attributes this "wall" to two coupled mechanisms — context-window degradation, in which early results are forgotten and the agent becomes inconsistent about which subtasks are already complete, and *goal drift*, in which models conditioned on their own accumulating trajectory inherit progressively noisier goal representations. The RUC-NLPIR long-horizon-agents survey (Dong et al., 2026) formalizes the same phenomenon in a nested task hierarchy: H1 tasks live within a single context window, H2 tasks span cross-context hours or days, and H3 tasks require experience accumulation across independent task streams. Each level demands a strictly stronger capability class (C1 ⊂ C2 ⊂ C3), and the survey's central architectural claim is that no policy π_θ can carry an H2 or H3 workload on its own — capability at long horizons is a property of the composite `π_θ ⊕ H`, where `H` is a surrounding *harness* that externalizes memory, control flow, and verification.

Hierarchy is the harness's dominant structural pattern. When a single agent is asked to plan, execute, verify, and remember at once, its context is loaded with all four responsibilities simultaneously, and the plan-representation is exactly the noise most vulnerable to overwriting. Splitting these roles across an explicit stack — a planner that owns objectives, executors that own actions, verifiers that own correctness — trades some coordination overhead for a large reduction in the effective context each component must reason over. The Plan-and-Execute pattern, now standard in production frameworks such as LangGraph, CrewAI, and Microsoft's Agent Framework, is the minimum viable expression of this principle; the frontier work extends it into three, four, and increasingly self-modifying tiers.

## 2. AgentOrchestra (Zhang et al., 2026) — The Tool-Environment-Agent Protocol

AgentOrchestra (arXiv:2506.12508) is representative of the current frontier: a hierarchical multi-agent framework built around a central *planner* that coordinates specialized *sub-agents* and dynamically extends the system's tool inventory during execution. Its architectural contribution is the **Tool-Environment-Agent (TEA) Protocol**, which the authors describe as "a unified abstraction that models these components as first-class, versioned resources with explicit lifecycles." Prompts, memory, tool code, agent code, environment specifications, and outputs are all tracked as versioned artifacts, and coordination between agents flows through this typed resource graph rather than through free-text messages.

Two properties of TEA matter for the durable-execution argument. First, versioning gives the system *traceability and reproducibility* — a replay of a long-horizon task can be reconstructed after the fact because every intermediate resource was named and persisted. Second, the protocol enables *self-evolution*: because tools and agent code are first-class resources with lifecycles, the running system can generate new sub-agents or rewrite existing ones without breaking upstream references. On the GAIA benchmark AgentOrchestra reaches 89.04% on the test set, and the authors report gains on scientific and mathematical reasoning suites as well. The paper positions TEA against Google's A2A and Anthropic's MCP — MCP handles the vertical LLM-to-tool link, A2A the horizontal peer-to-peer link, and TEA the internal resource graph a hierarchical orchestrator needs to reason about its own components as durable state.

## 3. HALO (Zheng et al., 2025) — Logic-Oriented Orchestration by MCTS

HALO (arXiv:2505.13516) makes the three-tier structure explicit. Its architecture is:

1. **A high-level planning agent** that decomposes the task into subtasks;
2. **Mid-level role-design agents** that *dynamically instantiate* specialist agents matched to each subtask (rather than drawing from a fixed cast of roles);
3. **Low-level inference agents** that execute the subtasks under the instantiated roles.

The paper's novel mechanism, *logic-oriented orchestration*, reformulates subtask execution as a structured workflow-search problem in which Monte Carlo Tree Search "systematically explores the agentic action space to construct optimal reasoning trajectories." Rather than commit to a single decomposition, HALO expands a search tree over candidate agent-graphs and prunes by rollout value. An Adaptive Prompt Refinement module cleans user queries at ingress. On MMLU Moral Scenarios HALO improves 13.3% over baselines; on MATH Algebra, 19.6%; the reported average lift over state-of-the-art multi-agent baselines is 14.4%. HALO is the cleanest published instance of the *planner / role-designer / executor* pattern that the durable-execution paper argues is the natural composition target for reflective loops.

## 4. The Broader Landscape

**AiScientist (Chen et al., 2026, arXiv:2604.13018)** targets multi-hour ML research engineering and organizes itself around *"thin control over thick state."* A top-level Orchestrator coordinates specialized sub-agents (implementer, experimenter, debugger) through a **File-as-Bus workspace** — a permission-scoped filesystem where every agent re-grounds on durable artifacts rather than reading peer outputs from memory. The empirical case for durability is unusually clean: an ablation that removes File-as-Bus drops PaperBench performance by 6.41 points and MLE-Bench Lite Any-Medal-% by 31.82 points. The system beats matched baselines by 9.92 (Gemini-3-Flash) and 11.15 (GLM-5) points on PaperBench. This is the strongest single data point in the current literature for the claim that hierarchical orchestration and durable state are not independent design choices — they are one mechanism.

**Curriculum-Guided Massive Multi-Agent System (Kar & Kumar, 2025, arXiv:2512.08545)** takes the hierarchy in an orthogonal direction: rather than depth (planner over executor), it uses *breadth* — a 64×64 grid of lightweight agents governed by a Thompson-Sampling curriculum manager and confidence-based (NLL) filtering, with selective oracle escalation. A spatial curriculum expands the operational region so agents "master easier central tasks before tackling harder peripheral ones." Evaluated on a spatially-grounded Tower of Hanoi benchmark, the system reduces oracle dependence and stabilizes long-range reasoning. The lesson for the paper: hierarchy need not be a strict tree; a lattice with an adaptive controller is a valid topology when task structure is spatial.

**Goal2Skill (Zylos 2026a)** implements the closed loop *plan → execute → verify → correct/continue* with a VLM planner maintaining structured task memory. Reported 32.4% success on RMBench against a 9.8% baseline, with the delta attributed specifically to structured memory plus explicit reflection.

**CORPGEN and MiRA (surveyed in Zylos 2026a)** demonstrate two additional hierarchy mechanisms. CORPGEN separates *strategic* (monthly), *tactical* (daily), and *operational* (per-cycle) layers, reporting 3.5× throughput vs. flat baselines (15.2% vs 4.3%). MiRA structures subgoals as a directed acyclic graph and *confines planning and replanning to the active node*, containing failure blast radius and enabling verification-driven local recovery without global replanning.

**Communication topology** is a second axis. The A2A/MCP/ACP/ANP survey (arXiv:2505.02279) distinguishes MCP's vertical hierarchical client-server design (LLM ↔ tools) from A2A's horizontal peer-to-peer design (agent ↔ agent). Production hierarchical stacks typically use MCP inside a layer and A2A between peer sub-agents within the same layer — hierarchy is the vertical spine and peer protocols fill the horizontal ribs.

**Memory** is a third axis. The Zylos tiered-memory pattern combines a lossless layer (tool calls, state changes, outputs verbatim) with a lossy layer that compresses intermediate reasoning; compression triggers around 4,000 tokens so agents keep "structured records of what they have done, rather than relying on implicit context window recall." Hierarchical stacks depend on this: a planner cannot supervise executors if its context is filled with executor transcripts.

## 5. Classical Antecedents: HTN and Hierarchical RL

Two pre-LLM traditions frame everything above. **Hierarchical Task Network (HTN) planning** decomposes compound tasks into primitive sub-tasks via named *methods*, and its 2025 revival is direct: ChatHTN queries an LLM on-demand whenever no symbolic method applies (arXiv:2605.07707), and Xu & Munoz-Avila (2025, arXiv:2511.12901) extend this with online method learning so LLM-generated decompositions are generalized and reused. LLM-generated heuristics reduce search effort on 83% of shared problems while preserving HTN's soundness guarantees. Modern hierarchical agent systems are, structurally, HTN planners with a neural decomposition oracle and neural leaf executors.

**Hierarchical Reinforcement Learning** contributes the *options framework* — temporally-abstract macro-actions defined by an initiation set, termination condition, and internal policy. The LDSC framework (arXiv:2503.19007) uses an LLM to propose subgoals, learns reusable options for each, and delegates primitive action selection to an RL policy; industrial and driving applications follow the same recipe. HALO's mid-level "role-designer" is, in options-framework terms, an option generator; AgentOrchestra's TEA-registered sub-agents are options with explicit lifecycles.

The re-emergence is not coincidence. Long-horizon control is a temporal credit-assignment problem, and both HTN and HRL solved that problem before LLMs existed by *composing* short-horizon competent policies inside longer-horizon selectors. LLM-agent hierarchies are the same solution with learned rather than hand-coded primitives.

## 6. Synthesis: Hierarchy as the Compositional Substrate for Reflection

The paper's specific claim — that reflective loops compose hierarchically, with a parent workflow reflecting on child workflow outputs — is exactly what the current literature is converging on, though it is rarely stated in those terms. Three observations from the sources above make the composition explicit.

First, reflection is already being invoked at multiple temporal scales inside single systems. OR-Agent and MobileUse implement *hierarchical reflection stacks* that aggregate feedback at action, trajectory, and task granularities — "similar to how optimization algorithms accumulate information over minibatches, epochs, and training trajectories." SmartFuzz's Reactive Collaborative Chain layers global and global-local reflection across planner, checker, and refiner agents in a strictly ordered workflow, and 360°REA maintains dual-level (local, global) experience pools with self/peer/supervisor assessment.

Second, hierarchy *is* what makes reflection scale. A flat ReAct + Reflexion agent must reflect over its entire trajectory in one context window; a hierarchical stack lets the executor reflect over its local subtrajectory, the planner reflect over the sequence of executor summaries, and a meta-planner reflect over cross-task patterns. This is the same insight HRL exploits — abstraction shortens the effective horizon each learner faces — applied to reflective updates rather than value updates. Zylos's HiPER framework operationalizes this as *hierarchical credit assignment*: "a planner receives credit at the subgoal level; an executor receives credit at the action level."

Third, hierarchical reflection *requires* durable state. Parent-agent reflection on child-agent outputs is only sound if the child outputs survive intact — File-as-Bus in AiScientist, TEA-versioned resources in AgentOrchestra, externalized goal state in InfiAgent and Mem0, and Zylos's checkpoint-and-reread pattern all serve the same function. Without durable artifacts, "the parent reflects on the child" degenerates into "the parent reflects on a lossy summary the child chose to emit," which is precisely the goal-drift channel Zylos (2026b) identifies as the dominant failure mode of naïve multi-agent trajectories. The paper's central substrate argument — that in-memory reflection is bounded and durable execution unbounds it — finds its cleanest empirical support in the hierarchical setting, because hierarchy is where cross-agent-boundary state is *forced* to be either persisted or lost.

The engineering implication is direct. A hierarchical reflective agent system in software engineering should treat each parent-child boundary as a durable-execution boundary: child outputs are workflow artifacts, parent reflection is a workflow step that consumes those artifacts and emits new ones, and the reflection loop at every level is durably replayable. This is the composition the paper argues for, and it is the composition the 2025-2026 literature has independently arrived at from three different starting points — planner/executor separation (AgentOrchestra, HALO), state externalization (AiScientist), and hierarchical credit assignment (HiPER, LDSC).
