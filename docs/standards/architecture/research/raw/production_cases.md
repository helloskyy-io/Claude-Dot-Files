Last validated: 2026-07-23

## 1. Overview: why production case studies matter

The paper's central claim — that durable execution is the missing substrate for production reflective agents — cannot be proven from first principles alone. It has to be shown in the field: real teams shipping real agents at real scale, hitting the same class of failure over and over, and either (a) buying a durable-execution platform to make the failures stop, (b) hand-rolling one that recreates ~60% of what platforms like Temporal already provide, or (c) shipping something that only appears to work because the horizon is short. The case studies below fall cleanly into all three buckets. They also reveal a pattern that is louder than any single vendor blog post: the industry has been discovering — in public — that "in-memory async loop plus retries" is not enough, and the vocabulary that describes what *is* enough (durable execution, checkpointing, replay, workflow IDs, activity retries) is the exact vocabulary Temporal shipped in 2019 for microservices.[^temporal-ai]

## 2. Per-system case studies

**Replit Agent → Temporal.** Replit is the most explicit adopter. They launched Replit Agent in September 2024 on "custom orchestration and reliability logic," and by November were already migrating to Temporal — a migration completed in "a couple of weeks."[^temporal-replit] The failure modes they cite are the canonical ones: agent processes crashing from memory pressure, model-provider outages mid-run, tool-call failures, and long jobs where users watched hours of state evaporate. Michele Catasta (Replit President) told LangChain, "It's a pretty bad user experience to have the agent get super far into something and then hit a catastrophic error, and you lose everything."[^langchain-replit] Post-migration Replit runs every agent as a Temporal Workflow with a unique Workflow ID (guaranteeing one-live-workflow-per-user-session), Activities for the non-deterministic LLM and tool boundaries, and Workflow Updates for human-in-the-loop pauses — the exact primitives Temporal designed for finance and inventory a half-decade earlier. Replit now reports "99.9999% trailing 30-day uptime" attributable to that layer.[^temporal-replit] Replit Agent 3 and Agent 4 extend the same architecture into parallel sub-agent execution, coordinated by a Temporal-managed manager/editor/verifier trio.[^replit-agent3][^replit-agent4]

**OpenAI Codex (web) and Lovable → Temporal.** Temporal's own materials — corroborated by the LLMOps database and multiple industry write-ups — name OpenAI's web-hosted Codex agent and Lovable as running on Temporal in production alongside Replit.[^temporal-ai][^zenml-temporal] Neither company publishes a first-party engineering post about the choice, but the pattern is telling: the largest LLM lab's own coding agent runs its orchestration on the same durable-execution primitive Replit adopted after a two-month scramble. This is exactly the "reinvent-then-adopt" arc the paper hypothesizes.

**Vercel AI SDK v7 + Workflow DevKit.** Vercel's public position is now that "code that's trivial to run locally falls apart the moment it needs to handle failures, restarts, and real traffic," and they built the Workflow SDK and a WorkflowAgent primitive in AI SDK v7 explicitly to plug that gap.[^vercel-workflow] Each tool call becomes a durable step; `getWritable()` yields persistent, resumable streams so a browser can drop and reconnect without losing tokens. This is the same architecture as Temporal, minted in-house because Vercel's target developer will not stand up a Temporal cluster. Notably, Vercel also ships a first-party Temporal integration for teams that want the platform underneath the SDK.[^temporal-vercel]

**Databricks + DBOS.** Databricks' own agent framework provides an async FastAPI wrapper with tracing and retries. For teams that need real durability guarantees on top of that, DBOS layers a Postgres-backed durable-execution library underneath — automatic checkpointing to Lakebase, resume-from-last-completed-step semantics, no full workflow restart.[^dbos-databricks] Databricks' own guide to agentic systems concedes that "production-grade orchestration requires automatic retry logic for transient failures, task queuing for high-volume workflows, and comprehensive observability."[^databricks-agents] That list is the durable-execution feature matrix.

**Anthropic Claude Code.** Reverse-engineered analyses (ZenML LLMOps, Substack write-ups) describe Claude Code as a single-threaded master loop codenamed `nO`, with a controlled subagent-dispatch subsystem (`I2A`/Task Agent) that spawns depth-limited children, and a context compressor (`wU2`) that triggers at ~92% of the window.[^zenml-claude-code] Public materials describe no durable-execution layer, no cross-process checkpoint format, no automatic resume after crash — durability there is provided by session storage on the local filesystem plus git-worktree isolation.[^anthropic-contain] This is fine for a developer-workstation harness; it is precisely why Claude Code cannot be lifted unmodified into a 24-hour autonomous agent without an external orchestrator.

**Sourcegraph Cody / Amp.** Sourcegraph's public architecture treats Amp as an agent product but Sourcegraph itself as a *context layer* — MCP server, deep search, code intelligence — rather than an orchestrator. Their 2026 "Agentic Coding" post describes the loop abstractly (context → plan → execute → test → refine) and does not document session persistence, checkpointing, or retry mechanisms.[^sourcegraph-agentic] The failure mode they emphasize is the "80% problem": agents finish visible work while silently missing cross-cutting changes. That is a correctness / context problem, not a durability problem — which itself is data: at Cody's usual horizon (single interactive session), durability doesn't dominate the failure budget yet.

**OpenAI Assistants API v1/v2.** The Assistants API introduced Threads (stateful conversations) and Runs (execution cycles) as managed abstractions on top of Chat Completions.[^openai-assistants] It required client polling to advance run state, locked the thread for the duration of a run, and had no client-facing durable-execution guarantees. OpenAI announced deprecation in 2026 in favor of the Responses API and Agents SDK, which the ecosystem is now wiring to Temporal directly.[^openai-shutdown][^temporal-ai] The Assistants API is a cautionary case: a first-party attempt to *be* the orchestration substrate that never delivered the durability primitives production teams needed.

**Cursor Agent.** Cursor's background agents run in Firecracker-isolated cloud VMs ("Anyrun"), with an Explore sub-agent that scopes context work into a child window.[^cursor-latency] There is no public claim of workflow-level durable execution; the durability is at the VM/repo-clone layer, and the coordination is filesystem + git. This is another point on the "harness, not orchestrator" curve — great UX at single-task horizon, no story for multi-day background jobs.

**LangGraph — the counter-example.** LangGraph is the framework most explicitly marketed as production-grade for agents, and it is the one Diagrid's engineering post dismantles most sharply: checkpoints in LangGraph are "a snapshot of state that you, the developer, are responsible for detecting the need to use, manually triggering, and coordinating at scale."[^diagrid-langgraph] There is no supervisor, no watchdog, no heartbeat, no cross-process coordination on `thread_id`; running behind a load balancer with `InMemorySaver` silently loses state; two processes recovering the same thread can double-execute. Independent write-ups reach the same conclusion — checkpoints are a save-point, not durable execution.[^oblique-langgraph] LangGraph *can* be made durable by combining `PostgresSaver` with an external supervisor and lock manager, which is functionally rebuilding the missing 60% of Temporal.

## 3. Cross-system patterns

Two patterns dominate. First, **every team that hit the multi-hour horizon adopted or rebuilt durable-execution primitives**: workflow IDs, activity boundaries around non-deterministic calls, automatic retries with exponential backoff, replay-based resume, human-in-the-loop parking, and persistent streams. Replit, OpenAI Codex, Lovable, Vercel Workflow, Databricks/DBOS, and the Temporal-plus-LangGraph combinations converge on this list independently. Second, **teams that stayed at the single-session horizon (Cody, Claude Code as a harness, Cursor foreground) got away with lighter durability** — filesystem persistence, git worktrees, in-process retries. This is not a contradiction; it is evidence for the horizon-length hypothesis the paper argues from. Below ~30 minutes on a workstation, durable execution is over-engineering. Above that, or across process boundaries, its absence becomes the dominant failure mode.

## 4. The "hand-rolled durability" pattern

The clearest signal is the reinvention arc. Vadim Beara compares the current state to "microservices in 2015: everyone knows they need it, but few have a clean abstraction."[^vadim-durable] Replit built custom orchestration, watched it fail, adopted Temporal, and finished the migration in weeks — a strong indication that the effort saved was months.[^temporal-replit] Vercel built its own Workflow DevKit, which reproduces the durable-step / retry / suspend-and-resume trio directly.[^vercel-workflow] Databricks/DBOS reproduces Postgres-backed checkpointing.[^dbos-databricks] GitHub Copilot orchestrator projects persist "full state and results in filesystem YAML" and include a "Repair Agent" that classifies failures and retries up to three times — a hand-rolled activity-retry-policy.[^copilot-orchestrator] Every one of these primitives — durable step, activity retry policy, workflow ID as idempotency key, human-in-the-loop signal, replay-based resume — already exists in Temporal (and Restate, Inngest, Cloudflare Workflows, AWS Step Functions Durable, and Azure Durable Functions). The industry is not disagreeing about the primitives. It is disagreeing about whether to buy them or build them, and — most importantly for this paper — *many teams did not know the primitives were a well-defined category* until after they'd hand-rolled 60% of one. The paper's contribution is naming that category as the missing substrate for reflective agents specifically, before more teams re-live the Replit arc.
