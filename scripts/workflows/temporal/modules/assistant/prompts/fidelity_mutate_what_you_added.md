**AND MUTATE WHAT *YOU* ADDED, NOT ONLY WHAT YOU INHERITED — the asymmetry is backwards.** Every mutation instruction here points at what the draft shipped. But a draft's tests have at least run against a real implementation, while **a correction pass's tests are written minutes before shipping with no second reader at all.** Measured across two consecutive passes on one PR: both times the vacuous test found was the reviewer's OWN, added in that pass, and both times it was caught by habit rather than by instruction.

**AND `0` OBSERVED WHERE YOU PREDICTED `0` IS A RESULT, NOT A NULL.** A predicted zero that comes back zero reads as a pass and is usually a HOLE — you predicted no test would fail because you already knew nothing guarded that line. **The correct response is to close the gap, not to record the prediction as met.** Two of one run's own changes had no guard at all and both came back exactly as predicted; the prediction is what made the absence visible, and stopping there would have shipped it.

**TWO PRACTICES WEAR THE WORD "MUTATION" AND ONLY ONE OF THEM IS UNIVERSAL. Decide which you owe before you spend a turn on it.**

- **The NEGATIVE CONTROL is the floor, and it is cheap: break the thing, watch your new test go red, restore.** One mutation per new assertion. This is the red step of red-green and you owe it on **any new test file and any test written to close a finding** — that is the Testing Standard's binding minimum, and this repo has measured what skipping it costs (a contract-grep blind to the raise channel, three credential exits live behind it). Never skip it, never size it away.
- **DISCRIMINATION ANALYSIS is the elaboration and it is NOT universal:** proving each of two guards fails *alone*, demonstrating a documented blind spot, re-running a recorded mutation whose evidence expired. **Owe it only where `MUTATION_DISCIPLINE`'s tier table already says to** — a guard, a gate, an authorization boundary, a new module or contract. On a scoped correction to known lines it is the maximum applied to everything, which that table names as *the absence of judgement, paid in wall-clock on every run*.

**NAME THE TIER AND THE PRACTICE IN THE DECISION LOG, in one line, before you mutate.** A pass that writes *"negative control only — six known items, no guard among them"* has made the judgement the table asks for and can be checked on it. A pass that silently runs five mutations on a typo fix has not, and neither has one that silently runs none on a merge gate.
